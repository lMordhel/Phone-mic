PHONE-MIC

Your phone is the microphone now.

scrcpy captures the phone mic over adb, PipeWire republishes it as Phone-Mic and every application you already own converts it into an ordinary input device. Nothing to install on the phone, no driver, no proprietary cable.

⤓ Install in one command ▸ See the panel

Why it feels native

4 rules it keeps

One process, one PipeWire node, one command. The phone stays a phone.

▸ Nothing on the phone

Wireless debugging plus scrcpy 3.2 or newer. No APK is built, published or required.

▸ One device, every app

Discord, OBS, browsers and recorders pick Phone-Mic from their own device list.

▸ Terminal only

No tray icon, no window, no updater in the background. The command is the interface.

▸ Survives the window

A systemd user service owns the bridge, so closing the terminal never cuts the audio.

The panel

one snapshot, real controls

Every reading is a real PipeWire control. GAIN is what applications receive, VOLUME is what arrives from the phone, and the meter opens its own 8 kHz capture client.

Keys, not menus

one keystroke per action

The dashboard is a TUI on purpose: no pointer, no navigation stack, no dialog that hides the reading you were watching.

  • C C Connect start the bridge service
  • X X Stop stop the bridge service
  • M M Mute virtual microphone on or off
  • A A Reroute move the stream back to the sink
  • D D Devices list PipeWire input devices
  • R R Reconnect reconnect adb
  • Tab Tab Gain / Volume switch the focused control
  • ←→ ← → ±5 % adjust the focused control
  • T T Theme picker with the twelve palettes
  • Q Q Quit the bridge keeps running

Not security tested

read before you install

phone-mic is a small utility, not a hardened product. What follows is stated plainly so nobody discovers it later.

[ ! ]

No security testing has been performed on phone-mic. There has been no security audit, no threat model, no penetration test, no fuzzing and no adversarial review of this codebase. The functional checks documented in the manual say nothing about whether it resists a malicious network, a malicious application on the same machine, or hostile input.

▲ The microphone stays open while it runs

While phone-mic-bridge is running, the phone captures audio continuously and publishes it as an input device every application can select. Stop the service when you do not need it.

▲ Wireless debugging is real access

Pairing gives this PC adb access to the phone: shell commands, file access, app installation. The pairing code is a credential. Remove the pairing on the phone when you are done, and keep wireless debugging off between sessions.

▲ No privilege boundary is added

The installer runs as your user and writes to ~/.config, ~/.local and a systemd user unit. It needs no root, and it also creates no sandbox: the bridge and the PipeWire node run with your permissions.

▲ The tests that exist are functional

The status table in the manual records manual checks on one machine (CachyOS, PipeWire 1.6, Hyprland): device present, bridge capturing, panel working, service reconnecting. It is not coverage of other distributions, other versions or hostile input.

If that is not acceptable for your use, do not install it. The manual has a complete uninstall that removes the unit, the PipeWire fragment and the state directories.

Install

no root, no PipeWire restart

The installer writes the PipeWire fragment, the phone-mic command, the phone-mic-bridge user unit and the documentation. It never restarts PipeWire, because that drops Bluetooth links and screencasts. Needs scrcpy 3.2 or newer, where --audio-source=mic appeared.

1 · dependencies (Arch and derivatives) 
$ sudo pacman -S --needed \
    pipewire-audio android-tools scrcpy
2 · the installer 
$ git clone https://github.com/lMordhel/Phone-mic.git
$ cd Phone-mic && ./packaging/install.sh
3 · check it, then talk 
$ phone-mic status
● Phone-Mic  PipeWire remap source            ACTIVE
● bridge      waiting for the phone           retrying

$ phone-mic start
● bridge      connected over Wi-Fi            50 ms buffer
then pick Phone-Mic in Discord, OBS or the browser microphone picker the service reconnects by itself
